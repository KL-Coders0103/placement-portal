# User Stories and Acceptance Criteria

## Actors
- **STU:** Student
- **ADM:** Placement administrator
- **OPS:** Platform operator
- **CO:** Company representative (future scope)
- **SYS:** Background/system process

Each story must be implemented with authorization, validation, error handling, observability, tests, and documentation.

## Epic A — Identity and account access

### STU-AUTH-01 Register
As a student, I want to create an account so I can use placement services.
- Valid fields are accepted and normalized.
- Duplicate email is rejected safely.
- Password is hashed; hash is never returned.
- Public payload cannot set privileged roles.

### STU-AUTH-02 Login
As a user, I want to sign in securely.
- Correct credentials produce the documented token response.
- Incorrect credentials return generic failure.
- Inactive accounts cannot authenticate.
- Rate limits and safe logging apply.

### STU-AUTH-03 Protected session
As an authenticated user, I want protected data to remain private.
- Missing, malformed, expired, and tampered tokens are rejected.
- Role and ownership are checked on every resource operation.
- Logout/revocation behavior is documented when implemented.

## Epic B — Student profile and resume

### STU-PRO-01 View profile
As a student, I want to view my placement profile.
- Only own profile is returned.
- Sensitive fields are omitted.
- Missing profile has a defined empty response.

### STU-PRO-02 Update profile
As a student, I want to maintain education, CGPA, branch, graduation year, skills, projects, and experience.
- Only allowlisted fields can be changed.
- Values are validated and normalized.
- Another student's profile cannot be modified by changing an ID.

### STU-RES-01 Upload resume
As a student, I want to upload my resume privately.
- Allowed type, size, and content are checked.
- Storage name is generated by server.
- File is not publicly served.
- Upload result includes safe metadata only.

### STU-RES-02 Review extracted data (future)
As a student, I want to correct parsed resume fields.
- Extraction shows source/evidence and confidence where available.
- User can edit before profile/matching use.
- Original resume is retained according to policy.

## Epic C — Jobs and eligibility

### ADM-JOB-01 Create job
As an admin, I want to create a job posting.
- Only authorized admin can create.
- Required fields and criteria are validated.
- Creator and timestamps are recorded.

### ADM-JOB-02 Publish/close job
As an admin, I want to control job visibility.
- Status transitions are valid and audited.
- Closed/expired jobs cannot accept applications.
- Existing applications remain accessible.

### STU-JOB-01 Browse jobs
As a student, I want to find open jobs.
- Only visible jobs are returned.
- Search/filter/pagination are stable.
- Job details show deadline and eligibility requirements.

### STU-ELG-01 Check eligibility
As a student, I want to know why I am or am not eligible.
- Response includes outcome and criterion-level reasons.
- Missing data is marked needs-review.
- Rule version is traceable.

### ADM-ELG-01 Override eligibility
As an authorized admin, I want to override a result when policy allows.
- Reason is mandatory.
- Actor/time/previous result are audited.
- Override does not erase original rule evaluation.

## Epic D — Applications

### STU-APP-01 Apply
As a student, I want to apply to an eligible open job.
- Job is open and deadline has not passed.
- Eligibility and required profile fields are checked.
- Duplicate student/job application is prevented by database constraint.
- Confirmation includes application ID and initial status.

### STU-APP-02 Track application
As a student, I want to see my applications and status history.
- Only own applications are returned.
- Status changes include timestamp and approved public reason.
- Empty state is clear.

### ADM-APP-01 Review applicants
As an admin, I want to review applicants for a job.
- Admin permission and job scope are verified.
- Results are paginated.
- Resume access is separately authorized.

### ADM-APP-02 Update status
As an admin, I want to shortlist/select/reject an applicant.
- Only allowed transitions are accepted.
- Reason and actor are recorded.
- Student receives notification when notification feature exists.
- AI score never changes status automatically.

## Epic E — Admin operations and reporting

### ADM-OPS-01 Manage students
As an admin, I want to search students by cohort/branch/skills.
- Search is paginated and filtered.
- Sensitive fields are minimized.
- Access is logged.

### ADM-OPS-02 View placement dashboard
As an admin, I want accurate summary metrics.
- Metrics are derived from persisted records.
- Date/cohort filters are explicit.
- Empty and loading states exist.

### ADM-OPS-03 Export report
As an admin, I want an authorized placement report.
- Export fields are allowlisted.
- Access is audited.
- Large exports are asynchronous and expire securely.

## Epic F — AI assistance (future)

### AI-01 Extract resume skills
As a student, I want skills extracted from my resume.
- Supported formats and parsing limitations are clear.
- Extraction result has parser version and timestamp.
- User can correct extracted fields.

### AI-02 Explain job match
As a student/admin, I want to understand alignment with a job.
- Score is accompanied by matched/missing skills and criteria.
- Score is reproducible for a versioned input.
- Result is advisory, not an automatic decision.

### AI-03 Monitor recommendation quality
As a product owner, I want to evaluate matching quality and fairness.
- Test set and metrics are documented.
- Cohort-level error analysis is reviewed.
- Release threshold and rollback criteria are approved.

## Epic G — Operations

### OPS-01 Configure environments
As an operator, I want secrets and config separated by environment.
- No credentials committed.
- Startup fails clearly for missing required config.
- Secret rotation is documented.

### OPS-02 Recover service
As an operator, I want backups and health monitoring.
- Backup restoration is tested.
- Health/readiness checks distinguish app and database state.
- Logs include request IDs but no secrets or resume contents.

## Definition of done
Story acceptance criteria pass; authorization and validation are server-side; tests include negative/boundary cases; accessibility/responsive behavior is checked; API/schema/docs are updated; no secrets or personal data are exposed.
